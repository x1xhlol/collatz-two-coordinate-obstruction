# Recorded validation

[`replay-record.json`](replay-record.json) records successful validation of the 357 bundled sources. The original run completed 357 compilations and 357 official Lean kernel checks, then failed at the generated audit's module header. Recovery preserved those 714 successful commands, checked all 357 proof objects again against a persisted dependency baseline, and compiled and checked the corrected complete audit. The record therefore contains 1,073 successful commands and one preserved failed audit command. Its main command list contains the original 714 commands and the corrected audit pair; the 357 additional kernel checks are in its `recovery` block.

The original pre-run external-object inventory was not retained. The complete dependency inventory supplied here was persisted before recovery and revalidated afterward. The record binds the original and corrected driver identities, the failed audit source and log, the original command progress, and the recovery executor.

The audit contains 11,718 module/constant rows, 11,703 distinct constant names, and 1,697 constants with Lean-encoded private names. Every row uses only `propext`, `Classical.choice`, and `Quot.sound`, or a subset of those axioms. The source inventory separately identifies 5,827 non-private named declarations, 441 private declarations, and 18 anonymous instances. Every named and private source declaration is covered by the audit; the complete module-header enumeration also includes compiler-generated constants.

[`relocation-record.json`](relocation-record.json) records the second-path check. It authenticates the copied full replay before and after, and freshly compiles and kernel-checks `TrapUnconditionalDeficit`, `TrapMicrocanonicalMassFloor`, and `TrapCentralMicrocanonical` against the copied dependency objects: six endpoint commands and two `--verify-only` authentication commands.

The historical records use `BUNDLE/` and `TOOLCHAIN/` as symbolic roots. Their `.replay/` and `.relocation-smoke/` paths describe the validation work directories. [`evidence-index.json`](evidence-index.json) gives exact hashes for the two records, [`generated-audit.lean`](generated-audit.lean), and the archives. `full-replay-logs.tar.gz` contains the 716 main-command logs; `relocation-logs.tar.gz` contains all eight relocation logs. `recovery-evidence.tar.gz` contains all 365 recovery artifacts, including the 357 additional kernel logs, original failure evidence, persisted baseline, and executor. Archive members use relative `logs/` or `recovery/` names, mapped by the index to the recorded paths and hashes. The exact original failed compiler diagnostic retains its original source path.

The release supplies sources, recipes, metadata, and logs. Compiled objects and dependency caches remain in the validation work directories. The full replay rebuilds every bundled application and Subspace module. External package revisions and the official toolchain are pinned; external Mathlib, package, and standard-library objects are hash-inventoried and are not rebuilt by this replay.

Follow the [reproduction instructions](../README.md#reproduce) for a clean 716-command replay with the corrected driver, a fresh `.replay/` directory, and its own record. The `--verify-only` command authenticates an existing complete replay and any recorded recovery evidence together with its compiled artifacts and dependencies.
